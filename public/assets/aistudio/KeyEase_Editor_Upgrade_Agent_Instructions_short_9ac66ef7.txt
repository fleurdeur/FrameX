1. KEYEASE: THE REFERENCE PLUGIN (an AE plugin, not your app)
================================================================
KeyEase is a normal After Effects CEP panel, shipped as .zip or .zxp. It is NOT part of the app. The app must run it unchanged, like any imported plugin. Do not modify KeyEase. Add no PC link, no localhost server, no LAN pairing, no token. Ignore the app-side/ folder in KeyEase.zip.

- Package layout: CSXS/manifest.xml (bundle com.keyease.panel, host AEFT, type Panel, 260x470, MainPath ./client/index.html, ScriptPath ./host/index.jsx, CEF flags --enable-nodejs --mixed-context), client/index.html, client/main.js, client/style.css, shared/curve-editor.js, host/index.jsx.
- How it works: panel UI calls window.__adobe_cep__.evalScript("KE.apply(x1,y1,x2,y2)"). The JSX applies the curve to selected keyframe pairs via the AE scripting API (app.project.activeItem, comp.selectedProperties, prop.selectedKeys, keyTime, keyValue, setTemporalEaseAtKey, setInterpolationTypeAtKey, KeyframeEase, beginUndoGroup) and returns ok:N or err:message.
- The panel also uses Node fs, path, os for a ~/.keyease folder. In the app these resolve to the plugin sandbox (2.4), so nothing outside it is touched.
- Curve = [x1,y1,x2,y2]. x clamped 0..1, y clamped -0.6..1.6.
- AE math per selected pair, avg = (v2 - v1) / dt:
  - Out ease of key 1: influence = clamp(x1*100, 0.1, 100), speed = (y1 / max(x1, .001)) * avg.
  - In ease of key 2: influence = clamp((1-x2)*100, 0.1, 100), speed = ((1-y2) / max(1-x2, .001)) * avg.
- Presets: Linear 0,0,1,1 | Ease .25,.1,.25,1 | In .42,0,1,1 | Out 0,0,.58,1 | InOut .42,0,.58,1 | Snappy .2,0,0,1 | Overshoot .34,1.56,.64,1 | BackIn .36,0,.66,-.56.

4. ALIGHT MOTION (.xml) IMPORTER
================================================================
Goal: lossless import that looks identical to Alight Motion. Study New_Project_25.xml and implement a parser (XmlPullParser or kotlinx-compatible) into the app's own project model.

4.1 Scene
- <scene> attributes: title, width/height (1080x1080), exportWidth/exportHeight, bgcolor (#AARRGGBB), totalTime (11091, milliseconds), fps (60), precompose, retime, modifiedTime, amver, ffver. Use same aspect ratio, resolution, frame rate. Keep time in ms, convert to frames only for display/export (frame = round(ms * fps / 1000)). Do not round totalTime to whole frames.
- <bookmark t="ms"/> (12 in this file, unsorted): import all as timeline markers, sorted, deduplicated.

4.2 Layer elements
- Found: shape (13), text (13), nullobj (6), drawing (1). Unknown element names: keep generically as raw layers, do not crash.
- Common attributes: id, label (optional), startTime/endTime (ms, layer in/out), parent (id of another layer; a child can appear before its parent, so resolve in two passes), fillType (color, media, intrinsic), mediaFillMode, blending (e.g. overlay), outTime (media trim), fillImage / fillVideo (content://media/... URIs), s=".rect" (shape type), type="perspective" (nulls), size, font (e.g. imported?name=FiraMonoNerdFont-Regular.ttf), wrapWidth, align.
- Children: <transform>, <fillColor value>, <color value>, <size value>, <opacity value>, <property name type value>, <effect id locallyApplied>, <content> (text), <stroke color width type points>.
- File order = layer order. Preserve it.

4.3 Transform and parenting
- <transform> has location (x,y,z in scene pixels), scale (sx,sy, 1.0 = 100%), rotation (degrees). Each is a constant value="..." or a list of <kf>.
- Scene space is 1080x1080, origin top-left, so a null at 540,540,0 is canvas center.
- A child's transform is relative to its parent (e.g. Rectangle 1 at 938,-15 inside a scaled null). Compose the full chain: world = parent * translate * rotate * scale. Assumption: anchor is the layer center. Verify by overlaying your render on an Alight Motion export of the same project.
- Nulls are invisible transform-only layers (type="perspective").
- Imported fonts: resolve imported?name=...ttf against the user's imported fonts. If missing, fall back to a default font and keep the font name in the model so it can be relinked.

4.4 Keyframes
<kf t v e>:
- t is normalized time within the layer: t = (time - startTime) / (endTime - startTime). Check: Null 1 has startTime 0, endTime 2282, kf t=0.339614 = 775 ms, exactly the first bookmark. t may be slightly below 0 or above 1 (e.g. -0.009238). Keep it, do not clamp.
- kf entries are NOT sorted in the file. Sort by t after parsing.
- v is a number, or x,y or x,y,z depending on the property.
- e is the easing and lives on the LATER key of a pair, governing the segment arriving at it (check: scale goes 2.36 to 1.0 with e on the 1.0 key). The first key has no e.
- Easing formats: cubicBezier x1 y1 x2 y2 (same model as KeyEase, y outside 0..1 possible), cyclic a b c d e, bounce a b. Parse name and float args. Implement cubicBezier exactly with Bezier.eval. Implement bounce and cyclic as well as you can, and ALWAYS keep the raw string so export and round trip stay lossless. Missing e = linear.
- Keyframes can also sit inside effect properties: <property name="end" type="float"><kf .../></property>.

4.5 Effects
- Seen in this file: com.alightcreative.effects.gaussianblur (strength), .fade (inTime, outTime), .texttransform (start, end, phase, component, anchor, offset, angle, scale, stretch, alpha, useFillColor, fillColor, rotateMode, scaleMode, autoRotate, rotateWeight, scaleWeight, radiusAdjust, overlap, shape, randomOrder, seed, easeIn, easeOut), .drawing.progress (start, end 0..100, with a bounce easing), .parenthelper. 4.6 Drawings and media

6. ROTO ENGINE
================================================================
Approach: two lightweight, mobile-optimized models.
- Mask: edge-AI variant of Segment Anything (SAM) or a MobileNet-based U-Net isolates the subject with minimal file size. Assumption: start with MobileSAM (or EdgeSAM) for prompted masks and a MobileNet U-Net as prompt-free fallback. Verify each model license before shipping.
- Tracking: a dense optical flow model plus a Video Object Segmentation (VOS) model tracks pixel movement and glides the mask across frames.
- Engine: separate module (:roto-engine) with its own interface, e.g. RotoEngine { load(models), segment(frame, prompt) -> mask, track(prevFrame, nextFrame, prevMask, state) -> mask, release() }. JNI + C++ with ncnn (Vulkan if available, CPU fallback). Assumption: ncnn, but ONNX Runtime Mobile is acceptable if a model does not convert; document the choice. Keep tracking state per clip. Run off the main thread, cap frame size for speed, reuse bitmaps and buffers.
- Pipeline: segment a key frame, then propagate forward and backward with optical flow warping refined by the VOS model. Re-anchor by running the mask model again when confidence drops, when mask area jumps, or when the user paints a correction on a frame. Store the result per frame, compressed.
- Model download on first use (mask model, flow and VOS model), stored in app files, checked by hash, resumable. One dialog shows total size, progress, cancel, retry, Wi-Fi hint.
- Two buttons:
  - Automatic background removal: segments the subject on the first frame of the clip range (user can tap to confirm or fix), tracks it across the whole range, produces an alpha mask layer.
  - Brush tool: has a switch "Remove background / Remove object". User paints on the preview with a semi-transparent red brush (brush size, hardness, eraser). The painted area is the prompt for the mask model. Remove background keeps the painted subject; Remove object cuts the painted object out. A stroke on any frame re-anchors tracking from that frame. Show the red overlay on the preview, never in the export.
- Result is stored as an editable mask or alpha layer in the project. Support undo and redo of strokes. Progress and cancel must work; cancel must leave the project unchanged.

8. PLUGINS: BROWSER, SWITCHES AND PROJECT BUTTONS
================================================================
App UI for the plugins in section 2: import, browse, switch on/off, use. There are no built-in plugins. Roto (6) and Depth map (7) are app features, not plugins.

8.1 Plugin registry
- PluginPackage(bundleId, name, version, kind (CEP or SCRIPTUI), extensions[], scripts[], installedAt, enabled, showInTimeline, fileNetworkAllowed, compat, rawAttributes), built from the parsed manifest in 2.1, or for a ScriptUI package from its script files. Unknown fields go to rawAttributes, never dropped.
- PluginRepository (DataStore for state, app files for packages): list, import(uri), enable, setShowInTimeline, uninstall, clearData. Expose a StateFlow of PluginUiState(installed, busy, message) through a ViewModel.
- A disabled plugin hides everywhere (timeline, FAB, effects list) but keeps its files, data and saved property values.

8.2 Plugin browser (new bottom button on the home page)
- Add a new button in the home page bottom bar, next to the existing ones, opening a Plugins screen. Settings gets no plugin layout, at most one row that opens this screen.
- Screen has an Import action (system file picker, .zip, .zxp, .jsx or .jsxbin, via Storage Access Framework) with progress and errors, a list of imported plugins, and an empty state explaining how to import.

8.3 Plugin card: enable and timeline switches
- As soon as a plugin is added it appears as a card with icon, name, version, kind (CEP or ScriptUI), signature note, an Enabled switch, a Show in timeline switch, a file and network permission switch (2.7), plus Use, Run probe, Clear data, Uninstall (with confirmation).
- Compute a status per plugin for the timeline UI (Shown, Hidden by you, Disabled, No panel UI, Unsupported) and show it as a chip next to the compatibility chip from 2.5. If the plugin has no panel UI (headless manifest, or a ScriptUI script that never opens a window), Show in timeline is disabled with the reason. Turning Enabled off also turns the timeline UI off.
- Use: opens the plugin panel in the project picker, or directly if a project is already open.
- Changes apply live to an open timeline, no restart. MaterialTheme.colorScheme only.

8.4 Projects: FAB plugin buttons
- In the projects screen, extend the FAB into an expandable menu (speed dial). Add one button per enabled plugin panel, with its icon and name, after the existing actions.
- Tapping a plugin button opens the plugin UI in the app's floating window (draggable, resizable, over the timeline) when Show in timeline is on, otherwise in a bottom sheet. Same window that hosts ScriptUI (2.7 C). Next to it, show the properties of whatever the plugin created or selected (effects, layers, keyframes) in the same property editor used for imported effects (slider, stepper, switch, vec2 pair, color picker, keyframe button). Edits update the preview live and are saved into the project.
- If no project is open, ask which project to use first. Keep FAB state in the ViewModel so it survives rotation.

8.5 Rules
- Plugins run off the main thread. A plugin that fails to load or crashes shows an error on its card and never affects the editor or other plugins.
- Sandbox and network rules are those in 2.4.

9. DONE WHEN
================================================================
- KeyEase, imported unmodified as .zip or .zxp, opens from the FAB and applies curves to the selected keyframes in the app, no PC, no network, no localhost (2.6).
- Any other .zip, .zxp, .jsx or .jsxbin plugin imports without crashing, and its compatibility report lists what is missing.
- Text Evo 2 loads on the script engine, uses the app's own engine and floating window, passes 2.8 with every gap listed in its report, and no decompiled source is stored or shown anywhere.
- Plugins switch on/off on their card, timeline UI status is shown, and an enabled plugin appears in the projects FAB with its properties.
- Playhead is stable, duration never flickers to 0.
- Alight Motion import passes 4.7 with nothing dropped.
- Mask, Roto and Depth Map flows work end to end, download on first use, with cancel and error states.
- Roto uses the mask model plus optical flow and VOS tracking, and a brush stroke re-anchors the track.
- No hardcoded colors, no main-thread blocking.
